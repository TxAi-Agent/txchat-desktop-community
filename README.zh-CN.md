# TxChat Desktop

[English](README.md)

基于 Electron 和 TypeScript 的桌面听写客户端，macOS 与 Windows 原生辅助程序源码均包含在同一仓库中。源码包含客户端界面、听写生命周期、账号与会员流程、支付二维码处理、自定义 AI 配置、词典、偏好设置、托盘与浮动窗口、诊断及更新协调逻辑。

这是面向开发者的源码分发。保留功能界面和状态机不代表已经提供背后的服务。本仓库不附带后端仓库、托管账号服务、语音模型、支付接入或更新分发服务；默认的服务、识别和更新适配入口均未配置。

## 开始使用

安装 Node.js 24 及 npm，然后在仓库根目录执行：

```sh
npm ci
npm run typecheck
npm test
npm run build
npm start
```

`npm ci` 会下载依赖，`npm start` 会重新构建后启动应用。在初始设置页面选择**进入本地开发界面**，即可在没有账号的情况下探索客户端。本地会话不会创建账号或服务令牌；无需后端或原生辅助程序即可查看各页面，使用本地词典和偏好设置。

## 保留的功能与默认行为

| 模块 | 包含的客户端代码 | 默认行为 |
| --- | --- | --- |
| 桌面界面 | 主窗口、状态、会员、自定义 AI、词典、偏好设置、托盘、浮动窗口 | 可用于本地开发；原生交互需要对应辅助程序 |
| 账号 | 登录、验证、会话恢复、令牌刷新、退出 | 服务适配器未配置 |
| 会员与支付 | 套餐、用量、订单状态、二维码展示及恢复 | 需要自建账号与计费服务；本地会话不会创建订单 |
| 识别 | 听写状态机、取消、音频采集及识别接口 | 默认识别适配器未配置，不附带真实 ASR 或模型 |
| 自定义 AI | 服务配置与请求处理 | 自行填写端点和凭据，没有内置端点 URL |
| 诊断与更新 | 客户端报告与更新状态机 | 诊断服务和更新后端需要开发者实现 |

主动选择 **local 本地服务**后，可以启用固定文本演示。这不是真实语音识别。配合原生辅助程序时，演示可以在内存中采集真实麦克风 PCM，但仍返回固定文字。浏览本地界面与采集麦克风是不同的操作。

开发者可通过[扩展说明](docs/extensions.md)中的类型化接口接入服务或模型。配置界面列出的服务或模型不代表已保证兼容或可用。运行接入真实服务的应用，需要实现并验证适合该应用的具体集成。

## 可选原生辅助程序

| 平台 | 原生构建要求 |
| --- | --- |
| macOS 14 或更高版本，Apple 芯片（arm64） | Xcode Command Line Tools，包含 Swift 和 Clang |
| Windows 11，x64 | .NET 10 SDK |

```sh
npm run build:native
```

辅助程序与平台集成源码已包含在本仓库中，无需另一个源码仓库。在应用的原生控制界面启动辅助程序，并授予相应系统权限后，才能使用麦克风采集、原生快捷键或文本写入。

原生文本写入需要主动启用，可能修改前台应用的文本。探索时请使用空白文档。Windows 会将已提交文字保留在剪贴板中；macOS 会尝试恢复原先内容。编译成功不代表所有目标应用的真实运行行为均已验证。

本仓库分发源码、原创图形素材及构建说明，不分发安装包、预编译辅助程序、已安装依赖副本或 CI 构建产物。
